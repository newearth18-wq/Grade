# Living classroom islands

The six additions build on existing authenticated submission records. They never write grades or award academic marks.

1. **Living companions.** Bunny, fox and owl move around the island using the existing renderer. Their feet and bodies animate, and greeting them or returning after a newly submitted assignment triggers a short celebration. Reduced motion, scene pause and active drag keep them still. Students can save a private name, limited to 24 characters, separately for each course/room/term.
2. **Progressive homes.** Distinct actual uploads create a construction area, tent (1 work), hut (3), treehouse (5), then a banyan home (10). Stages have different geometry rather than scaling a complete house. Lavender, mint and peach colors are free cosmetic selections. Resubmitting one assignment cannot create extra house parts. Score-driven growth of the banyan remains unchanged.
3. **Class cooperation.** The server counts live assignments and active, live students to compute received submissions / expected submissions. Student responses expose aggregate counts only, with no names, missing-work lists or other students' marks/files. At 60/80/100 percent the scene adds a waterfall, bridge and garden island. Students and teachers with edit access may ask the server to persist the earned stage; the server recomputes eligibility and only advances it. Rewards remain for the course's term even when new assignments lower the current percentage. Teacher-recorded paper submissions count as received work for the class, while individual upload XP retains its existing rules.
4. **Work album.** The student's own currently graded assignments become cards with actual marks (including zero), latest submission-revision files and teacher feedback. Images and downloads use the existing authenticated file endpoints. No public gallery, extra file copies or other students' portfolio data are created.
5. **Today's goals.** Students choose up to three actionable assignments in the same course. Returning to the goal opens the existing submission flow. Progress is derived from submissions; returned work remains actionable. Goals reset by the Bangkok calendar date. Existing completed goals can be retained, but already-submitted assignments cannot be newly selected just to manufacture completion. There is no goal penalty or bonus mark.
6. **Celebration scenes.** First submission unfolds a sprout, a first successful revision shows butterflies, and completing all current assignments shows a companion parade. The strongest simultaneous milestone takes precedence. Actual upload XP and new unlocks still require refreshed server confirmation. Sound remains opt-in and reduced motion is respected.

## Persistence and access

`settings` stores a small `student_island:<user>:<course>` JSON value containing revision, companion species/name/personality, house color and today's selected assignment IDs. Species is validated against bunny/fox/owl; all are available immediately. A null species on older profiles retains the existing browser choice until the student explicitly saves one. The student-only GET/PATCH `/api/island/:courseId` checks live active enrollment. PATCH accepts only known fields and uses optimistic revision plus atomic compare-and-swap. No client-supplied student ID is accepted. Class stages use `class_island:<course>` and POST `/api/island/:courseId/community`; eligibility never comes from a client stage value. Daily growth memories also retain the chosen species for replay.

State exports only the signed-in student's personal profiles. Class queries use scoped CTE counts and return aggregates. Prefix reads use indexed key ranges to avoid D1's LIKE-pattern length limit. Cosmetic selections that predate this update remain in browser storage; names/colors/goals are stored on the server. Fresh restored course IDs start with fresh personal preferences; earned appearances are recalculated from restored work. These preferences do not change the existing grade/file backup format.

## Verification

`tests/adventure-life.mjs` exercises real uploads, account and course boundaries, invalid/cross-room goals, optimistic races, aggregate privacy, server-only reward claims, persistent class milestones, teacher review, resubmission counts, daily rollover and revoked enrollment. `tests/adventure-life-pure.mjs` checks Bangkok dates, house thresholds, non-rounded milestone gates, own current-revision albums including zero marks, celebration classification, companion movement/pause and geometry reuse. Existing journey, island, bubble and teacher-upgrade checks cover preserved behavior. Browser QA uses an isolated local classroom.
