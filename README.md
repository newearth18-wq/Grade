# Grade — ระบบส่งงานและผลการเรียน

เว็บภาษาไทยสำหรับครูหนึ่งคนที่ดูแลหลายวิชาและหลายห้อง นักเรียนมีบัญชีแยกกัน ฐานข้อมูล Cloudflare D1 และไฟล์ Cloudflare R2 ใช้งานได้หลายปีและหลายภาคเรียน

## ความสามารถ

- นักเรียนส่งรูป JPG/PNG/WEBP หรือ PDF/DOCX/XLSX แนบได้ 5 ไฟล์ ไฟล์ละ 10 MB รวม 25 MB
- ครูตรวจรูป ให้คะแนนและข้อเสนอแนะ ส่งคืนให้แก้ และดูไฟล์จากรอบก่อนหน้า
- นักเรียนดูคะแนนงาน งานที่ขาด คำชี้แจงและไฟล์ตัวอย่างของงานที่ค้าง
- เพิ่มนักเรียน แก้ชื่อและเลขที่ในรายวิชา พัก/คืนการลงทะเบียน ตั้งรหัสผ่านชั่วคราว และบังคับเปลี่ยนก่อนใช้
- แยกปีการศึกษา เทอม วิชา และห้อง คะแนนและรายชื่อในเทอมเก่าไม่ถูกทับ การนำเข้ารหัสนักเรียนเดิมใช้บัญชีเดิม
- นำเข้า Excel (.xlsx/.xls), CSV, Word (.docx) และ PDF ที่มีข้อความ ผ่านหน้าจับคู่คอลัมน์และแก้รายชื่อก่อนบันทึก ไฟล์ละ 15 MB, PDF ไม่เกิน 30 หน้า, นักเรียนครั้งละไม่เกิน 100 คน
- PDF สแกนและ Word .doc แบบเก่าต้องแปลงเป็นไฟล์ที่มีข้อความหรือใช้ตารางตรวจรายชื่อ ระบบรุ่นนี้ไม่มี OCR
- หน้าแดชบอร์ดสถิติการส่ง ตรวจ งานค้าง และนักเรียนที่ต้องติดตาม พร้อมตัวกรองภาคเรียนและวิชา
- คะแนนเก็บตามสัดส่วนงาน + กลางภาค + ปลายภาค รวม 100 ปรับสัดส่วนต่อรายวิชาได้ เกรด 0, 1, 1.5, 2, 2.5, 3, 3.5, 4 และสถานะ ร/มส
- เผยแพร่ผลการเรียนหลังตรวจงานและกรอกคะแนนสอบครบ การแก้คะแนน งาน หรือรายชื่อยกเลิกการเผยแพร่อัตโนมัติ งานที่ไม่ส่งนับ 0 เมื่อสรุปผล งานที่รอตรวจหรือถูกส่งคืนต้องจัดการก่อนเผยแพร่
- ส่งออก Excel รายชื่อและผลการเรียน สำรองข้อมูลและประวัติการแก้ไขเป็น JSON (ไม่รวมไฟล์งานหรือรหัสผ่าน)
- เก็บรายวิชาเป็นประวัติเพื่อปิดรับงานและป้องกันการแก้ไข และเปิดกลับได้

## เริ่มใช้งาน

1. เปิดเว็บไซต์ สร้างบัญชีครูครั้งแรก ตั้งรหัสผ่านอย่างน้อย 10 ตัวอักษร ไม่มีบัญชีหรือรหัสผ่านเริ่มต้นฝังในโค้ด
2. เพิ่มปีการศึกษา/ภาคเรียน แล้วสร้างรายวิชาและห้อง
3. เพิ่มหรือนำเข้ารายชื่อนักเรียน เลือกคอลัมน์รหัส ชื่อ นามสกุล (ถ้าแยก) และเลขที่ ตรวจให้ถูกต้องก่อนบันทึก
4. ดาวน์โหลดรหัสผ่านชั่วคราวที่สร้างใหม่ แล้วแจ้งให้นักเรียนแต่ละคน นักเรียนต้องเปลี่ยนรหัสผ่านก่อนใช้งาน รหัสผ่านไม่แสดงซ้ำหลังปิดตาราง
5. สร้างงาน กำหนดคะแนนเต็มและวันส่ง (เวลาไทย) แนบโจทย์/ตัวอย่าง นักเรียนเปิดงานและส่งรูปจากมือถือได้
6. ตรวจงานในเมนูตรวจงาน กรอกคะแนนสอบในผลการเรียน แล้วกดเผยแพร่
7. จบเทอมให้เก็บรายวิชาเป็นประวัติ เทอมใหม่ใช้รายชื่อจากวิชาเดิมได้โดยไม่คัดลอกคะแนนเก่า

## การใช้กับ SGS

เมนูนำเข้า/ส่งออก > ไฟล์ต้นแบบ SGS: อัปโหลดไฟล์ `.xlsx` จากโรงเรียน เลือกแผ่นงาน แถวแรก และคอลัมน์รหัสนักเรียน/คะแนนแต่ละส่วน/เกรด ระบบจับคู่รหัสนักเรียน แสดงเซลล์ที่จะกรอก และไม่เขียนทับเซลล์เดิมจนกว่าจะเลือกอนุญาต

- คอลัมน์ที่เว้นว่างจะไม่ถูกแก้ไข เซลล์อื่น รูปแบบพื้นฐาน สูตร และแผ่นงานอื่นเก็บไว้
- นักเรียนที่ไม่มีในต้นแบบหรือมีรหัสซ้ำจะบล็อกการส่งออกเพื่อป้องกันคะแนนผิดคน
- ใช้ไฟล์ต้นแบบที่รหัสนักเรียนเป็นข้อความ โดยเฉพาะรหัสมีเลข 0 นำหน้า
- ไม่รองรับ macros (.xlsm), charts หรือคุณสมบัติ Excel ขั้นสูงบางชนิด ควรใช้ไฟล์ต้นแบบตารางคะแนนและตรวจไฟล์หลังส่งออก
- ทดสอบกับต้นแบบจำลองแล้ว ยังไม่มีไฟล์ SGS จริงของโรงเรียน จึงยังไม่ยืนยันว่าไฟล์ใดๆ จะนำเข้าระบบ SGS ได้ทันที ต้องตรวจรูปแบบและขั้นตอนของโรงเรียนจากไฟล์จริง
- ระบบไม่เรียก API หรือเข้าสู่ระบบ SGS แทนครู และไม่เก็บรหัสผ่าน SGS

## พัฒนาในเครื่อง

ต้องมี Node.js 22.13 ขึ้นไปและ npm

```sh
npm ci
npm run db:generate  # เฉพาะเมื่อแก้ db/schema.ts
npm run build
```

ใช้ D1/R2 จำลองในเครื่อง แทนบริการจริง ข้อมูลเก็บที่ `.wrangler/state` และไม่อยู่ใน Git

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_secret_aaron_stack.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_green_wallop.sql
npm run dev
```

ใช้ไฟล์ migration แต่ละไฟล์เพียงครั้งเดียวในฐานข้อมูลนั้น เรียงลำดับเมื่อมี migration ใหม่ `npm start` ใช้ทดสอบ Worker ที่ build แล้ว

Sites อ่าน `.openai/hosting.json` สำหรับ D1/R2 และใช้ build metadata ที่สร้างขึ้นในการเผยแพร่ การเผยแพร่ใช้ฐานข้อมูลและไฟล์ของจริงที่แยกจากข้อมูลทดสอบในเครื่อง

## การทดสอบ

```sh
node node_modules/typescript/bin/tsc --noEmit
node tests/integration.mjs  # ฐานข้อมูลทดสอบว่างเท่านั้น
```

**Integration test ใช้ได้เฉพาะฐานข้อมูลทดสอบว่าง** สคริปต์จะหยุดเมื่อมีบัญชีครูแล้ว สร้างเฉพาะข้อมูลจำลอง ไม่ควรรันกับข้อมูลโรงเรียน ตั้ง `GRADE_TEST_URL` เพื่อใช้เครื่องทดสอบที่แยกไว้

ใช้ `node tests/built-worker.mjs` หลัง build เพื่อทดสอบ Worker ที่ compile แล้วในฐานข้อมูลและไฟล์จำลองแยกอัตโนมัติ โดยไม่แตะข้อมูลในเครื่องหรือข้อมูลโรงเรียน

ตรวจการตั้งค่าครูครั้งเดียว สิทธิ์ครู/นักเรียน การนำเข้าแบบไม่บันทึกบางส่วน การแยกปี/เทอม ประวัติรายชื่อและไฟล์รุ่นเก่า ขอบเขตคะแนน งานคืนแก้ การเผยแพร่/ถอนผลคะแนน และไฟล์ส่วนตัว `tests/grades-and-export.mjs` ตรวจการคำนวณและกรอกต้นแบบ Excel หลัง bundle โมดูลสำหรับทดสอบตาม README ใน tests

## สิทธิ์และการเก็บข้อมูล

รหัสผ่าน PBKDF2-SHA256 พร้อม salt แยกบัญชี เซสชันแบบสุ่มเก็บเฉพาะ hash ในฐานข้อมูล Cookies เป็น HttpOnly, SameSite=Lax และ Secure บน HTTPS จำกัดการลองรหัสผ่าน สิทธิ์ตรวจที่ server ทุก endpoint ไฟล์ถูกเก็บแบบส่วนตัว ข้อมูลและไฟล์ของนักเรียนคนอื่นไม่ส่งมายังเบราว์เซอร์นักเรียน

เว็บไซต์ที่สร้างผ่าน Sites เริ่มเป็นส่วนตัวสำหรับเจ้าของ การให้นักเรียนเข้าลิงก์ต้องปรับสิทธิ์เข้าชมเว็บไซต์ให้เหมาะกับโรงเรียนเพิ่มเติม โดยสิทธิ์ครู/นักเรียนในแอปยังตรวจแยกจากสิทธิ์เข้าชมเว็บไซต์

บัญชีครูรุ่นแรกใช้ครูผู้ดูแลคนเดียว หากโรงเรียนต้องการครูหลายคน ต้องเพิ่มการจัดสรรรายวิชาและสิทธิ์ก่อนเปิดบัญชีครูเพิ่มเติม

## โครงสร้างสำคัญ

- `app/grade-app.tsx` และ `components/grade/`: หน้าครู/นักเรียน
- `app/api/[...path]/route.ts`: API ตรวจสิทธิ์และบันทึกข้อมูล
- `lib/auth.ts`, `lib/server.ts`: บัญชี เซสชัน และฐานข้อมูล
- `lib/grades.ts`: คำนวณคะแนนและเกรด
- `lib/files-client.ts`: อ่านรายชื่อ สร้าง Excel และกรอกต้นแบบ SGS (ประมวลผลไฟล์รายชื่อในเบราว์เซอร์)
- `db/schema.ts`, `drizzle/`: Schema และ migration
